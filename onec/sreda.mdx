## 1. Документация 1С — в контекст агента

Claude Code не должен угадывать имена объектов и методов. Источники:

| Что | Где взять | Куда положить |
|---|---|---|
| Синтаксис-помощник платформы 8.3 | из установленной платформы или ИТС | выдержки — `onec/` в этой базе |
| Справка конфигурации БП КЗ 3.0 | Конфигуратор → Справка | что нужно — `onec/` |
| Метаданные базы `lakomka` | выгрузка конфигурации в файлы | локально на стенде, не в git |
| HTTP-сервисы, расширения | ИТС, «Разработка интерфейсов» | `onec/http-servisy` |

<Tip>
  Не выкладывать дословно закрытые материалы ИТС — пересказ своими словами и ссылки. Полные тексты — локально на стенде.
</Tip>

## 2. Как агент работает с конфигурацией

<Tabs>
  <Tab title="Конфигуратор">
    Привычно, ничего не ставить. Цикл: правка в Конфигураторе → выгрузка `1cv8 DESIGNER /DumpConfigToFiles src -Extension bilem` → Claude читает `src/`, предлагает правки → загрузка обратно `/LoadConfigFromFiles`. Агент видит код, но не видит живые метаданные.
  </Tab>
  <Tab title="EDT + EDT-MCP">
    [EDT-MCP](https://github.com/DitriXNew/EDT-MCP) — MCP-плагин внутри 1C:EDT. Claude Code через него читает и пишет модули, проверяет запросы, создаёт объекты метаданных. Проект EDT сразу лежит текстом в git — выгрузка не нужна.

    Минусы: EDT тяжёлый (Java, 8+ ГБ памяти), к нему надо привыкнуть. Подключение — по README плагина, потом сервер `edt` в `.mcp.json` репо `bilem.cfe`.
  </Tab>
</Tabs>

## 3. MCP самой cfe

Когда база опубликована на IIS и в cfe есть `POST /hs/bilem/mcp/<токен>`, в `.mcp.json` уже прописан сервер `bilem`:

```json
"bilem": { "type": "http", "url": "http://localhost/lakomka/hs/bilem/mcp/${BILEM_TOKEN}" }
```

Токен — в переменной окружения `BILEM_TOKEN`. После этого Claude Code сам проверяет свои методы как MCP-клиент.
