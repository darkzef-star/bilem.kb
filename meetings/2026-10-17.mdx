## Главное

- **Позиция Славы:** уйти от `.cfe`, чтобы не плодить «зоопарк» точек отказа. Схема: служба Windows `Bilem.service` + OData + MCP. Права режем на уровне MCP: в MCP описаны только наши инструменты, остальное недоступно.
- **Позиция Стаса:** без своей роли права не удержать. Если дать боту типового бухгалтера и снять галочки (например, отправку ЭСФ), при обновлении типовой конфигурации права слетят, и бот получит полный доступ. Надёжно только **расширение со своей ролью** (вида `CRM_SKP`): база остаётся типовой, обновляется как обычно, роль не перезатирается. Код расширения можно зашифровать.
- **OData** публикует состав объектов, но права чтения и записи определяет пользователь 1С, под которым идёт подключение. Значит, отдельный технический пользователь нужен в любом случае.

## Вариант без `.cfe`: «волшебная кнопка»

При онбординге админ один раз вводит логин и пароль администратора 1С. Служба через COM-коннектор (V83) создаёт пользователя Bilem со сложным паролем и типовыми ролями под конфигурацию. Дальше набор доступных действий ограничивает MCP.

- **Замечание Стаса (ИБ):** бот сам создаёт пользователя с широким доступом к OData, и это без контроля человека. Для массового рынка Казахстана допустимо, для Enterprise нет.
- **Ответ:** для Enterprise отдельный план с ручной настройкой прав под требования ИБ клиента (закрытый туннель, белый IP, ограниченный набор услуг).
- **Компромисс по записи:** технический пользователь по умолчанию только читает, запись (счета на оплату, акты сверки) отдельным правом. Проводки бот не делает.

<Warning>
  **Открытый вопрос:** можно ли без `.cfe` надёжно ограничить права так, чтобы они не слетали при обновлениях. Если нет, делаем `.cfe` со своей ролью (по одной на конфигурацию, их 5–6, отличаются мало).
</Warning>

## Зачем MCP у клиента

Вопрос Стаса: зачем MCP на стороне клиента, если можно отдавать OData через VPN прямо на наш сервер. Ответ Славы:

- MCP позволяет подключить **любой** клиент (ChatGPT, Claude, Hermes, OpenClaw) в пару кликов, без чтения документации API.
- Для облачного подключения ChatGPT и Claude обязателен **OAuth**: пользователь входит в кабинет Bilem, лицензия проверяется на каждом обращении (например, токен на сутки).
- В облачном (платном) MCP появится слой ролей: кто из сотрудников какие услуги может вызывать.
- **Идея Стаса, принята:** разграничивать доступ по каналам и номерам телефонов (белые и чёрные списки).

## Модель: open core

| Уровень | Что входит |
| --- | --- |
| Бесплатно | Локальный MCP на GitHub, ставишь сам по инструкции и видео. Цель: звёзды, комьюнити, обратная связь через issues |
| Настройка под ключ | Около 5 000 ₸: подключаем за клиента |
| Платный облачный MCP | OAuth, тарифы, роли по услугам, каналы (WhatsApp, Telegram, Claude) |
| Enterprise | Свой периметр, локальная модель, требования ИБ |
| Партнёры | 1С-франчайзи и аутсорсинговые бухгалтерии перепродают сервис своим клиентам с разделом выручки |

Целевой пользователь — не айтишник: «поставил, нажал два-три раза, и 1С отвечает».
