### Что сделано

- **`print_power_of_attorney`** — доверенность из 1С: `number` / `last`, без них — поиск по `employee` (часть ФИО) и `period`. Форма Д-1 по образцу Славы: шапка организации (БИН, адрес, счёт и банк), «Дата выдачи» / «действительна по» (в 1С не указан срок — по настройке, 10 дней), «Выдана», удостоверение личности, «На получение от», «Активов по», перечень с количеством прописью; подписи руководителя и главбуха; печать и подпись — поверх строки руководителя. Файл — `Документы\Bilem\<база>\Доверенности\Доверенность №… от … — <ФИО> (<база>).pdf`.
- **Удостоверение личности и ФИО** — служебные объекты состава OData (регистры ФИО и паспортных данных физлиц, виды документов, сотрудники и должности организаций, справочник «Физические лица»). Читаются только внутри печати доверенности; в ответе MCP, в журнале и в аудите их нет (тест). «Физические лица» на «Доступе» — по-прежнему под замком и выключены для ИИ. Роли чтения для служебных объектов подбираются при настройке базы и «Применить» (по ПравоДоступа, самая узкая роль).
- **`print_reconciliation`** — акт сверки по регистру бухгалтерии, как типовой «Акт сверки» 1С: счета расчётов из списка типового документа (с субсчетами), субконто 1 — контрагент, 2 — договор; проводки между счетами расчётов одного контрагента (зачёт аванса) в акт не идут. Параметры: `counterparty` (БИН или название), `period_from`, `period_to` (пусто — прошлый квартал по настройке), `contract`, `organization`. Несколько договоров — разбивка по договорам. Макет по образцу Славы: левая половина — наши данные, правая пустая или зеркальная (галочка), итог прописью «задолженность в пользу …»; подписант контрагента — «/\_\_\_\_/». В ответе — сальдо, обороты, `as_of`. Файл — `…\Акты сверки\Акт сверки — <контрагент> — <период> (<база>).pdf`.
- **Сверка с 1С**: акты сверки, уже сохранённые в учебной базе, пересчитаны инструментом за те же периоды — 2 из 3 совпали по оборотам и числу документов до копейки, в третьем на один документ больше: он проведён позже, чем был сохранён старый акт. Предварительно проверено на 5 актах базы.
- **`send_document`**: `reconciliation` — на любой e-mail (не назван — e-mail контрагента из 1С), `power_of_attorney` — только на адреса из «Списка адресов для отправки доверенностей» (иначе отказ до печати). Тексты писем — свои для доверенности и акта, РУ/КЗ.
- **«Печатные формы» — вариант A**: сверху база и «Скопировать из другой базы…»; подвкладки **Общее · Счёт · Доверенность · Акт сверки** с точкой статуса (зелёная — всё задано, жёлтая — чего не хватает, строкой внутри); таблица настроек по ТЗ; внизу «Сохранить» и «Пробный документ…» (печатает форму текущей подвкладки). Руководитель и главный бухгалтер: пусто — из 1С (регистр «Ответственные лица организаций», загружается при настройке базы и кнопкой «Реквизиты из 1С…», в поле — серой подсказкой), своё значение главнее. Строка «Формы: … скоро» убрана.
- **Счёт**: галочки «что печатать», «Образец платёжного поручения», «Примечание внизу».
- **Журнал аудита** пишет и печать из окна агента («Пробный документ…»), с пометкой Bilem Agent вместо программы MCP.
- Попутно: `bilem-agent access --apply` — применить к 1С без изменений (после обновления агента); «лишние роли» при повторной настройке больше не показываются для ролей, добавленных «Доступом».

### Заметки

- В учебных базах регистр «Ответственные лица организаций» пуст — подписи руководителя и главбуха печатаются как «/\_\_\_\_\_\_/», пока их не задали на «Общем»; точка «Общего» жёлтая с подсказкой.
- Строки аудита с пользователем Tailscale проверены пробным клиентом с заголовками; через настоящий `tailscale serve` — на приёмке.
- Стандартный текст вступления акта в config.json не сохраняется (можно улучшать в новых версиях); своё — сохраняется.

### Приёмка Славы

1. «Печатные формы» → v19 → «Доверенность» → «Пробный документ…» → доверенность из 1С: поля как в образце, удостоверение подставлено, печать и подпись на месте. В Claude: «отправь последнюю доверенность из v19 на чужой адрес» → отказ; на адрес из «Списка адресов для отправки доверенностей» → уходит.
2. «Акт сверки» → «Пробный документ…» (контрагент, квартал) → сальдо и обороты как в отчёте 1С «Акт сверки» за тот же период; правая половина пустая; галочка «зеркально» → заполнена.
3. Журнал аудита: строки `print` / `send` с программой, источником и хешем; ИИН и номера удостоверения там нет.

## 18.10.2026 · Часть C — SMTP и send_document: готово к приёмке

<Check>
  Коммит **`83d7e18`**, CI зелёный — прогон 39128638345, 2 мин 29 с, тесты **112 из 112**. Цепочка целиком проверена на стенде с **локальной SMTP-заглушкой** (127.0.0.1, наружу ничего не уходило). Настоящая почта — шаги 1–2 приёмки Славы (пароль приложения вводит он сам).

### Что сделано

- **Вкладка «SMTP»** — после «Печатных форм», на каждую базу: сервер, порт, SSL/TLS (465) или STARTTLS (587), логин, **пароль приложения** (в окне — точки, хранится только зашифрованным для этой машины — DPAPI; поле очищается после сохранения, рядом — «сохранён»), имя и адрес отправителя; готовые подсказки Gmail / Mail.ru / Yandex / Outlook (сервер, порт, где взять пароль приложения); **«Проверить — письмо себе»**; **«Свои адреса»** (адрес — кто, по одному в строке); скрытая копия себе (вкл. по умолчанию); лимиты 10 / час, 50 / день; шаблоны темы и текста РУ / КЗ с подстановками и подпись; рубильник **«Почта выключена»** (и в меню трея); серый блок «Подтверждение с телефона, права по людям, цепочки одобрений · Облако».
- **Свой SMTP-клиент** (без сторонних библиотек): `System.Net.Mail` не умеет SSL сразу при подключении (465 — Mail.ru, Яндекс). SSL сразу и STARTTLS, AUTH PLAIN/LOGIN, письмо «текст + PDF», кириллица в теме и имени вложения — RFC 2047. В тексте ошибки сервера пароля нет.
- **`send_document`** (`base`, `document: invoice`, `number` / `last`, `counterparty`, `to`, `note` ≤ 300): делает PDF счёта → письмо **ждёт подтверждения**: окно агента поверх остальных + уведомление в трее; в окне — первая страница PDF, «Открыть PDF», кому (несколько e-mail у контрагента — выбор), скрытая копия, тема, текст → **«Отправить» / «Отмена»** (мимо модели; крестик = «Отмена»). Ответ ИИ — `id` и «ждёт подтверждения», адрес — замаскирован. Итог — **`send_status(id)`**: pending / sent / cancelled / failed (текст SMTP).
- **Адресат — только из двух мест**: e-mail контрагента счёта из 1С или «Свои адреса»; любой другой — «адрес не найден ни в карточке контрагента, ни в своих адресах — добавьте его во вкладке SMTP». `to` не указан — e-mail контрагента из 1С. Один адресат + скрытая копия; вложение — только PDF агента.
- **E-mail контрагента из 1С**: регистр «Контактная информация» — **служебный объект** состава OData: в дереве «Доступа» его нет, инструментам ИИ он недоступен (там и данные физлиц), читается только внутри агента фильтром «этот контрагент + тип «адрес эл. почты»» (`Объект eq cast(guid'…', 'Catalog_Контрагенты')` — составной тип, простое `guid'…'` 1С не принимает). Добавляется при настройке базы; v19, v20, v21 перенастроены (состав 44, «Доступ» не сброшен, ложных «изменений» нет).
- **Журнал агента**: «Счёт №4 от 13.04.2022 (v21) отправлен на t\*\*\*@…, подтвердил …, 18.10 15:41»; отмена и ошибки — так же; содержимого письма нет. Для лимитов хранятся только времена отправки.

### Приёмка Земли (v21 → локальная заглушка SMTP)

| Проверка | Итог |
| --- | --- |
| Адрес не из 1С и не из своих | отказ с текстом из ТЗ, письма нет |
| Свой адрес → окно → «Отправить» | окно появилось поверх; `send_status` → `sent`; заглушка получила одно письмо: два RCPT (адресат + скрытая копия отправителю), тема и текст по шаблону с припиской, вложение «Счёт №4 от 13.04.2022 — … (v21).pdf» — валидный PDF |
| «Отмена» | `cancelled`, в заглушке новых писем нет |
| Рубильник «Почта выключена» | отказ |
| Лимиты, «не настроена», без окна | отказы (юнит-тесты) |
| Пароль | в config.json — только DPAPI; в журнале, в тексте ошибки SMTP, в ответе MCP — нет (тест `Password_NeverInPlainText`) |

После проверки настройки заглушки у v21 убраны, заглушка остановлена. Снимок окна подтверждения (там счёт) — Славе, в журнал не кладём.

### Приёмка Славы (настоящая почта)

1. «SMTP» → база v19 → «Почта: Gmail» (или другая) → логин, **пароль приложения** → «Сохранить» → «Проверить — письмо себе».
2. В «Свои адреса» — тестовый адрес → «Сохранить» → в Claude (новая сессия — чтобы увидеть новые инструменты): «отправь счёт №4 из v19 на (тестовый адрес)» → на стенде всплывет окно → «Отправить». Окно подтверждения — на компьютере, где открыт агент (стенд, RDP).
