**Старт:** сейчас (заход 4 закрыт, `f0449c5`) · **Язык:** C#, .NET Framework 4.8, WinForms — [0011](/decisions/0011-csharp-net48) · **Репо:** `skp-kz/bilem.agent`, коммитим как в публичный ([правила](/process/repo-bilem-agent)) · **Отчёт:** журнал `stand/agent-app-v01-log`

## Цель

Админ скачивает один zip, запускает от администратора, выбирает базу, вводит пароль администратора 1С → через минуту его Claude Code / Claude Desktop / Cursor отвечает на вопросы из 1С. То, что уже доказано скриптом и прототипом MCP, — перенести в настоящую программу, ничего не потеряв.

## Структура

```text
src/
  Bilem.Agent.Core/   — вся логика (без UI): шаги онбординга, конфиг, OData-клиент, MCP-сервер, журнал
  Bilem.Agent.Com/    — помощник COM к 1С, собирается дважды: bilem-com32.exe (x86) и bilem-com64.exe (x64)
  Bilem.Agent/        — окно (WinForms) + CLI в одном exe
tests/                — юнит-тесты Core
```

- SDK-style csproj, `TargetFramework=net48`, `dotnet build` (ссылочные сборки — Microsoft.NETFramework.ReferenceAssemblies). Ничего из API новее 4.8; внешние пакеты — минимум и только со совместимостью net48.
- Помощник COM — отдельный процесс нужной разрядности (выбирается по реестру / платформе), задание и ответ — JSON через stdin/stdout. Упал COM — падает помощник, а не агент.
- Сборка в GitHub Actions (windows-runner) → артефакт `bilem-agent-<версия>.zip` (без подписи, без MSI).

## CLI — то же, что кнопки (чтобы ты могла тестировать без мыши)

```text
bilem-agent diag  --base <путь>                  — диагностика и план, ничего не меняет
bilem-agent setup --base <путь> --admin <логин> [--password <пароль>] [--slug <имя>] [--enable-iis]
bilem-agent verify [--slug <имя>]                — проверки шага 10 (чтение, запрет записи, 401, 403)
bilem-agent list                                   — подключённые базы
bilem-agent remove --slug <имя>                  — убрать базу: публикация, пул, пользователь bilem (по флагу)
bilem-agent serve                                  — MCP-сервер без окна
bilem-agent connect claude-code|claude-desktop|cursor — прописать MCP в клиента
```

Без аргументов exe открывает окно. Код возврата: 0 — успех, 1 — любая проверка не прошла.

## Онбординг — перенос спайка без потерь

- Все шаги и все находки `setup-spike.ps1` и `docs/known-issues.md` (1–10) — каждая находка должна быть учтена в коде (в журнал — таблица «находка → где в коде»).
- Шаги идемпотентны: «проверить → сделать → перепроверить»; повторный запуск продолжает с упавшего. Состояние — `C:\ProgramData\Bilem\`.
- **Новое:** отдельный пул IIS на каждую базу (`Bilem_<slug>`), права на папку базы — только её пулу (твоё предложение из захода 2).
- **Новое:** поиск баз — чтение `ibases.v8i` всех профилей (`C:\Users\*\AppData\Roaming\1C\1CEStart\`), в окне — список с выбором; плюс «Указать папку вручную». В v0.1 — только файловые базы; серверные показать с пометкой «скоро».
- Пароль `bilem` — DPAPI в области **LocalMachine** + права на файл только у Администраторов и SYSTEM (чтобы потом прочитала служба). Пароль администратора 1С не хранится нигде.
- Конфиг `C:\ProgramData\Bilem\config.json`: базы (slug, путь, конфигурация, версия, адрес OData, пул), порт MCP, токен (DPAPI). Без данных из 1С.

## MCP — перенос прототипа захода 4

- Streamable HTTP на `127.0.0.1:<порт>/mcp/<токен>`, запросы с `Origin` — 403 (как в прототипе). Официальный C# SDK — если встаёт на net48; иначе своя минимальная реализация (`initialize`, `tools/list`, `tools/call`, `ping`) по спецификации MCP — в журнал, что выбрала и почему.
- Инструменты — те же, что в прототипе (`list_bases`, `whoami`, `find_counterparty`, `cash_balance`), с тем же форматом ответа. **Сверка:** на одних и тех же вопросах ответы C# = ответам Node-прототипа.
- **Изменение по итогам захода 4:** если баз несколько и `base` не указан — не ошибка, а ответ **по всем базам сразу**, с подписью базы у каждой строки. В прототипе модель делала 2–3 лишних вызова (ошибка → `list_bases` → по каждой базе), ответ шёл 16–25 с. Ошибка остаётся только для неизвестного `base`. Сумму по базам не складывать — это делает модель, если базы разные.
- Условия по счетам в остатках — в `$filter`, не в параметрах `Balance(…)` (лимит сегмента пути http.sys, known-issues п. 10).
- Правило MCP-слоя с первого дня: проводки по счетам оплаты труда и с физлицами в аналитике наружу не отдаются (список счетов — в профиле конфигурации).
- MCP работает, пока открыто окно (сворачивается в трей), или через `bilem-agent serve`. Служба Windows — v0.2.
- Журнал запросов: время, база, инструмент, длительность, итог — **без данных ответа**.

## Окно (вариант A, классические контролы Windows)

Заголовок «Bilem Agent — локальный режим», строка состояния внизу (MCP работает / остановлен, число баз, порт). Вкладки:

| Вкладка | v0.1 |
|---|---|
| **Базы 1С** | список подключённых (slug, конфигурация, статус); «Добавить…» → выбор из найденных или папка → логин/пароль админа 1С → окно «Настройка» со списком шагов и галочками + живой журнал; «Проверить», «Удалить» |
| **Подключение** | адрес MCP + «Скопировать», кнопки «Подключить к Claude Code / Claude Desktop / Cursor», «Сменить токен»; дисклеймер про токен в адресе; блок «Облако bilem» — серый, «скоро», ссылка на лист ожидания |
| **Доступ к данным** | только просмотр: роли `bilem`, состав OData (число объектов + список), «запись запрещена — проверено ДД.ММ» |
| **Журнал** | запросы MCP и события настройки; «Собрать отчёт для поддержки» (zip без паролей и токенов) |
| **О программе** | версия, bilem.ai, GitHub, лист ожидания |

Запуск требует прав администратора (манифест `requireAdministrator`). Весь текст — по-русски, строки в одном файле ресурсов (казахский — потом). Ошибки — человеческим текстом «что случилось → что делать» из known-issues.

## Приёмка

<Steps>
  <Step title="Сборка">
    GitHub Actions собирает zip; юнит-тесты Core зелёные.
  </Step>
  <Step title="CLI на чистой копии">
    `setup` на новой копии эталона — зелёный, быстрее 30 с; вторая база — свой пул; `verify` — всё зелёное; повторный `setup` — ничего не ломает; `remove` — убирает чисто.
  </Step>
  <Step title="MCP">
    `connect claude-code` → в новой сессии Claude Code четыре вопроса из захода 4 — ответы = Node-прототипу, лишних вызовов из-за `base` нет; без токена — 401; с другого адреса — недоступно.
  </Step>
  <Step title="Окно — принимает Слава">
    Слава по RDP на стенде: добавить базу мышкой от начала до конца, подключить к Claude, спросить «сколько денег».
  </Step>
</Steps>

## Не в v0.1

Облачный режим, служба Windows, MSI, самообновление, подпись кода, серверные базы, путь Б (RLS), доступ из локальной сети и белый список IP, запись в 1С (черновик счёта), SMTP, PDF.

## Правила

- Работаешь на копиях эталона (`C:\ip_primin\etalon` — не трогать), рабочие публикации стенда не трогаешь.
- Коммиты как в публичный репо, проверка перед каждым push (lock-файлы — можно, они исключены из проверки). Крупные шаги — отдельными коммитами (скелет → Core-онбординг → CLI → MCP → окно → CI).
- Данные учебной базы — только в чат Славе; в журнал, репо, базу знаний — нет.
- Журнал — страница `stand/agent-app-v01-log` (создай по правилам [/kb](/process/kb-zapis)): что сделано, хеши, решения, вопросы Славе.
