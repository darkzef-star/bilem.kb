## Заход 4 — сейчас: минимальный MCP поверх OData (18.10.2026)

**Цель:** первая полная цепочка «ИИ → MCP → OData → 1С». Claude Code на стенде отвечает на вопросы из 1С через наш MCP. Это **одноразовый прототип**: проверяем схему и формат инструментов, а не пишем приложение.

<Steps>
  <Step title="Сервер">
    Node + официальный MCP SDK (`@modelcontextprotocol/sdk`), транспорт Streamable HTTP. Код — `spike/mcp/` в `bilem.agent`. Слушает **только 127.0.0.1**, адрес с токеном в пути: `http://127.0.0.1:<порт>/mcp/<токен>` (как в режиме разработчика по решению Славы). Токен генерируется при первом запуске и хранится локально, в репо и журнал не попадает.
  </Step>
  <Step title="Базы">
    Конфиг — список баз, опубликованных `setup-spike.ps1`: короткое имя (slug), адрес OData на 127.0.0.1, логин `bilem`, путь к DPAPI-файлу с паролем (его же пишет скрипт). Для теста — **две базы** (например, публикации v14 и v17), чтобы сразу проверить работу с несколькими базами. Каждый инструмент принимает необязательный параметр `base`; если база одна — можно не указывать, если несколько и не указано — понятная ошибка со списком.
  </Step>
  <Step title="Инструменты (только чтение)">
    - `list_bases` — какие базы подключены: slug, конфигурация, версия.
    - `whoami` — по базе: конфигурация и версия (берутся при онбординге и хранятся в конфиге — OData их не отдаёт), организации из справочника «Организации», пользователь `bilem`, время ответа.
    - `find_counterparty(query)` — поиск контрагента по части наименования или БИН/ИИН: наименование, БИН/ИИН, не больше 10 строк.
    - `cash_balance(date?)` — остаток денег на дату по организациям: касса и банк отдельно, по плану счетов «Типовой» (счета денежных средств КЗ — 1010, 1030 и т. п.; проверь по плану счетов базы). Через виртуальную таблицу остатков регистра бухгалтерии. Если по OData не получается за разумное время — опиши, на чём споткнулся, и сдай без него. Ответы — компактный JSON, суммы числами, без лишних полей. Описания инструментов — по-русски, так, чтобы модель понимала, когда что вызывать.
  </Step>
  <Step title="Подключение к Claude Code на стенде">
    `claude mcp add --transport http bilem-local http://127.0.0.1:<порт>/mcp/<токен>`. В новой сессии Claude Code спросить по-человечески: «какие базы подключены?», «что это за организация?», «найди контрагента …», «сколько у нас денег на сегодня?» — убедиться, что модель сама выбирает инструменты.
  </Step>
  <Step title="Проверки">
    - Без токена или с неверным — 401; с другого адреса машины — недоступно (слушаем только 127.0.0.1).
    - Ответы `cash_balance` сверить с отчётом «Оборотно-сальдовая ведомость» по тем же счетам в 1С (под администратором) — совпадает до тиына.
    - Время ответа каждого инструмента — в журнал.
  </Step>
  <Step title="Коммит">
    `spike/mcp/` + в README раздел «Как подключить MCP к Claude Code / Claude Desktop / Cursor». Проверка перед push по правилам репо (токены, адреса, данные). Хеш — в журнал.
  </Step>
</Steps>

<Note>
  Ответы инструментов содержат данные учебной базы — **в чат Славе можно, в журнал, репо и базу знаний — нет.** В журнал — только «работает / не работает», время, коды, число строк.
</Note>

## Прогон онбординга N (если нужна свежая база)

<Steps>
  <Step title="Копия эталона">
    `Copy-Item C:\ip_primin\etalon C:\ip_primin\vN -Recurse` — следующий свободный номер.
  </Step>
  <Step title="Онбординг">
    `powershell -ExecutionPolicy Bypass -File <путь к setup-spike.ps1> -BasePath C:\ip_primin\vN -AdminUser Бухгалтер -Apply -EnableIIS`
  </Step>
  <Step title="Упало — чини скрипт, не базу">
    Найди причину, **исправь скрипт**, новый прогон с новой копии (N+1). Ничего не чинить руками в базе или IIS.
  </Step>
</Steps>
