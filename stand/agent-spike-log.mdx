### 1. Аутентификация публикации

- Анонимный вход публикации переведён на **удостоверение пула** Bilem1C (в IIS: анонимная проверка подлинности, пустое имя пользователя — значит, удостоверение пула).
- Права на изменение папки базы — **только пулу Bilem1C**. IUSR и IIS_IUSRS скрипт больше не выдаёт. Проверено на v11: у файла базы из учёток IIS — только пул; наследуемые права папки-родителя (администраторы, система, «Пользователи» на чтение) скрипт не трогает.
- Вариант чище — **отдельный пул на каждую базу** (например Bilem_имя-публикации). Сейчас пул Bilem1C общий, и при нескольких базах на машине у пула есть доступ ко всем. Отдельный пул изолирует базы друг от друга; цена — по процессу IIS на базу. Предлагаю сделать так в программе, в спайке оставил общий.

### 2. Состав OData — шире

Было 10 объектов, стало **43** (в метаданных — 130 наборов с табличными частями). Добавлены по конфигурации КЗ:

- **справочники:** подразделения, номенклатурные группы, классификатор единиц, типы цен, склады, кассы, банки, статьи движения денежных средств, статьи затрат, ставки НДС;
- **деньги:** платёжные поручения входящие и исходящие, платёжные ордера на поступление и списание, приходные и расходные кассовые ордера, оплата от покупателя платёжной картой;
- **продажи:** возврат товаров от покупателя, счёт-фактура выданный, чек ККМ, отчёт о розничных продажах;
- **покупки:** поступление товаров и услуг, поступление доп. расходов, возврат товаров поставщику, счёт-фактура полученный;
- **склад:** перемещение, списание, оприходование товаров;
- **расчёты:** акт сверки, корректировка долга, доверенность;
- **регистры сведений:** курсы валют, цены номенклатуры.

**Не включено:** зарплата, кадры, физлица; также **авансовые отчёты** (подотчётные лица — физлица) и **контактные лица** контрагентов. Обрати внимание: регистр бухгалтерии «Типовой» содержит **все** проводки, в том числе по зарплате, — ограничивать это будет слой MCP.

### 3. Уборка

- Публикаций v1–v7 в IIS нет (v6 и v7 удалены раньше). Пул Bilem1C перезапущен, чтобы отпустить файлы старых копий.
- **Копии v1–v7 удалить не смог:** защита Claude Code считает папку с копиями системным путём и блокирует удаление. Обходить не стал — нужно удалить вручную (одна команда в PowerShell от администратора, отдал Славе в чат).
- Остались: v8, v9, v10, v11, v12 и их публикации (все только 127.0.0.1), эталон не тронут.

Не трогал — «Полные права».

## 18.10.2026 · Apply: v4–v8 — ГОТОВО, контрольный v9 прошёл с первого раза

<Check>
  **v9 — с чистой копии, скрипт не менялся (хеш тот же): ГОТОВО за 10,6 с от копии.** По IP стенда — **403**, с 127.0.0.1 под bilem — 200.
</Check>

**Конфигурация:** «Бухгалтерия для Казахстана, редакция 3.0» (БухгалтерияДляКазахстана), версия **3.0.41.2**. **БСП есть** (справочник «Пользователи»). Платформа 8.3.27.2342, 32-бит.

**Флаги:** Apply, EnableIIS; вход — Бухгалтер, пароль пустой.

### Прогоны

| N | Где закончилось | Причина | Что исправлено в скрипте |
| --- | --- | --- | --- |
| v4 | шаг 5, «Конфигурация:  () версии», затем падение; код выхода 0 | PowerShell не видит свойства объектов 1С по COM напрямую (Metadata пустой) и разворачивает коллекции 1С (роли, справочники) в массивы при возврате из функции. Падение не дошло до кода выхода — обёртка перезапуска отдала 0 | Свойства объектов 1С — через вспомогательные P и SetP (InvokeMember, результат возвращается без разворачивания), методы — напрямую. | v5 | шаг 6, после записи пользователя | Запуск из PowerShell 7 передал свой PSModulePath, Windows PowerShell 5.1 подхватил модули 7-ки и упал на шифровании пароля (TypeData ... already present). Пользователь уже записан, а пароль не сохранён | В PowerShell 5.1 в PSModulePath остаются только пути WindowsPowerShell. Пароль шифруется в DPAPI до записи пользователя |
| v6 | шаг 9, установка «Ограничений по IP» | Install-WindowsFeature нет в 32-битном PowerShell (а он у нас из-за 32-битной 1С) | Компоненты Windows — через 64-битный dism (одинаково на сервере и клиенте), шаг 8 тоже. Вывод webinst — в правильной кодировке |
| v7 | шаг 10, HTTP 500 | «Ошибка режима доступа к файлу базы данных»: при анонимной аутентификации IIS модуль 1С открывает файлы базы от имени IUSR, а права были только у пула и IIS_IUSRS | Права на папку базы — ещё и IUSR (по SID, имя локализовано). В заходе 2 заменено на вход от имени пула |
