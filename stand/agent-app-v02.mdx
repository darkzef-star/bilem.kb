## Приёмка PDF, пачка 2 — 18.10.2026 (сделать сейчас)

Пачка 1 **принята** (18.10): счёт №4 из v19 пришёл на Мак прямо в ответе MCP — с логотипом, печатью поверх строки подписи и подписью. v20 печатается голой, потому что для неё не заполнена вкладка «Печатные формы» — это не баг, но молчать об этом нельзя.

<Steps>
  <Step title="1. «Счёт от имени»">
    Во вкладке «Печатные формы» — новое поле **«Счёт от имени»** (свободный текст, на каждую базу; по умолчанию «Бухгалтер»). Печатается в строке «Исполнитель \_\_\_\_\_\_ /\<значение>/». Должность или Фамилия И.О. — решает пользователь, из 1С не подставляем.
  </Step>
  <Step title="2. Предупреждение, если форма не настроена">
    Если у базы не заданы логотип, печать или подпись — `print_invoice` всё равно печатает, но в ответе MCP явное предупреждение: «Печатная форма \<база> не настроена: нет логотипа, печати, подписи». В окне агента — жёлтая метка на вкладке «Печатные формы» у этой базы.
  </Step>
  <Step title="3. Адрес поставщика — из 1С">
    По умолчанию адрес берётся из контактной информации организации в 1С; поле во вкладке — только переопределение. Новая база сразу печатается с адресом.

    **Исправление 18.10 (Слава):** окно «Реквизиты из 1С» с логином и паролем администратора — **убрать**. Отдельный запрос пароля ради адреса не нужен. Адрес читает пользователь `bilem` через OData: контактная информация организации добавляется в состав OData **при онбординге** (там пароль администратора уже вводится) и при «Применить» на «Доступе». Для уже подключённых баз (v19, v20) — один раз при следующем «Применить». Если адреса в OData нет — печатаем без него, в ответе MCP предупреждение «адрес организации не найден — заполните во вкладке «Печатные формы»», поле во вкладке — ручной ввод.
  </Step>
  <Step title="4. Имя файла — с базой">
    `Счёт №4 от 13.04.2022 — ТОО SOLVER GROUP (v19).pdf` — и на диске, и в имени ресурса MCP. Сейчас у v19 и v20 одно имя, на клиенте файлы путаются.
  </Step>
  <Step title="5. Поиск счетов">
    `print_invoice` принимает `counterparty` (БИН или часть названия) и `period`. Без `number`/`last` — список найденных счетов (номер, дата, покупатель, сумма), без печати; с `number` или `last` — печать. Только чтение. (Сейчас Claude знает только номер последнего счёта и не может найти другой счёт на того же покупателя.)
  </Step>
  <Step title="6. v20 — скопировать оформление">
    В v20: «Скопировать из другой базы…» → v19, затем счёт №4 из v20 — Славе.
  </Step>
  <Step title="7. Вкладка «MCP» — без инструкций, ссылка на документацию">
    Макет: `minidesk/docs/mockups/bilem-agent-mcp-tab.html` (утвердил Слава 18.10). Три блока:

    - **«Сервер MCP»:** зелёная точка «Работает · только этот компьютер (127.0.0.1:8796)» + «Остановить» справа; «Адрес:» (токен точками) + «Скопировать»; «Показать токен» + «Сменить токен…» (с подтверждением «старый адрес перестанет работать во всех подключённых программах»); одна строка предупреждения: «Токен в адресе — ключ к данным 1С. Не пересылайте и не публикуйте.»
    - **«Подключить программу»:** иконка приложения (та же зелёная) + крупная ссылка **docs.bilem.ai/connect ↗** + текст «Инструкции по подключению ваших LLM и агентов — в документации. Понадобится адрес MCP выше.» Клик по блоку открывает браузер.
    - Строка «Выписка устарела через [3] рабочих дня — ИИ предупредит, что остаток и должники могут быть неточны» (из части D v0.3) — оставить, под блоком «Сервер MCP».
    - **Блок «Облако bilem — скоро» и ссылку «Лист ожидания» — убрать** (Слава, 18.10). Про облако рассказывает docs.bilem.ai/connect.

    Кнопки «Подключить к Claude Code / Claude Desktop / Cursor» — **убрать** (вместе с кодом записи их конфигов). Длинное предупреждение — убрать.
  </Step>
</Steps>

**Не трогать:** положение печати (поверх строки подписи — так и задумано) и текст «Внимание! Оплата…» в шапке (стандартный, кто захочет — поменяет во вкладке руками).

**Проверка:** новая база без настроек → счёт с адресом из 1С + предупреждение; v19 и v20 — с логотипом, печатью, подписью; поиск «счета Solver Group за 2022» → список. Снимки — только Славе в чат.

## Приёмка PDF, пачка 1 — 18.10.2026 (принята)

<Steps>
  <Step title="1. Печать — на место">
    Круг печати — поверх строки «Исполнитель \_\_\_\_\_\_ /Бухгалтер/», левым краем примерно на конец линии подписи. Положение — в мм от строки подписи, чтобы при длинной таблице печать ехала вместе со строкой.
  </Step>
  <Step title="2. PDF — сразу из MCP">
    В ответе `print_invoice`: сам PDF (`type: "resource"`, `mimeType: "application/pdf"`, `blob` base64), PNG первой страницы (`type: "image"`, ~1000 px) и текст (номер, дата, покупатель, сумма, путь на стенде).
  </Step>
  <Step title="3. «Последний» — по дате">
    `last` — последний счёт по дате, при одинаковой дате — по номеру.
  </Step>
  <Step title="4. Папки — по базам и видам документов">
    `Документы\Bilem\<имя базы>\<вид документа>\` — `…\v21\Счета\`, `…\v21\Доверенности\`, `…\v21\Акты сверки\`. Папки вида создаются при первом документе. Старые файлы из `Документы\Bilem\Счета\` — перенести при первом запуске.
  </Step>
</Steps>

## Изменение 18.10.2026 — запись только по белому списку ([0013](/decisions/0013-belyj-spisok-zapisi))

- **Колонка «Запись» активна только у белого списка** (в коде, не в конфиге, + тест): **Счёт на оплату покупателю, Доверенность, Акт сверки взаиморасчётов, Контрагенты, Банковские счета (контрагентов), Договоры контрагентов**. У остальных — **замок** с подсказкой «Bilem не создаёт документы, которые меняют бухгалтерский учёт. Нужно — напишите нам (Сервис → GitHub)».
- По умолчанию запись выключена и для белого списка. Счётчики «запись 0 из N» — только то, что можно включить.
- Строка-обещание над деревом, на «О программе», в README и на сайте: **«Bilem не меняет ваш бухгалтерский учёт: читает данные и готовит только счета, доверенности, акты сверки и карточки контрагентов — после вашего подтверждения, непроведёнными.»**

## Часть 1 — вкладка «Доступ» (было «Доступ к данным»)

- Выбор базы, строка состояния «Запись запрещена — проверено …».
- Дерево разделов 1С (из подсистем конфигурации; запасная раскладка из профиля) с колонками «Чтение» / «Запись», три состояния галочек, человеческие имена (синонимы), «Применить» / «Отменить» со сводкой.
- «Применить»: слой MCP — сразу; слой 1С — с паролем администратора (состав OData, роли по `ПравоДоступа`), автоматическая проверка.
- Проведение и удаление — никогда ([0002](/decisions/0002-ne-trogaem-uchet)), тест. Изменения — в журнал.
- Платное — метка «Облако» на своём месте; блок «Доступ по людям · Облако».

## Часть 2 — вкладка «Печатные формы»

**Цель:** спросить ИИ «дай счёт на оплату № …» → PDF с логотипом, печатью и подписью этой базы. Счёт уже есть в 1С — только чтение и печать; черновики — v0.3.

- Вкладка на каждую базу: «Скопировать из другой базы…»; плейсхолдеры «Логотип», «Печать», «Подпись (факсимиле)» с лимитами (логотип ≤ 200 КБ, ≤ 1000×400 px; печать PNG прозрачный ≤ 200 КБ; подпись PNG прозрачный ≤ 100 КБ), файлы — `C:\ProgramData\Bilem\bases\<имя>\print\` (только Администраторы и SYSTEM); «Счёт от имени», текст в шапке, Кбе/КНП; «Формы» (Счёт — работает; Доверенность, Акт сверки — «скоро»); «Пробный счёт…».
- PDF: PDFsharp + MigraDoc (MIT), PT Sans (OFL, казахские буквы), макет как печатная форма 1С.
- MCP: `print_invoice` (`base`; `number` или `last`; поиск — `counterparty`, `period`) → PDF в `Документы\Bilem\<база>\Счета\` + сам PDF и превью в ответе.

## Правила

- На копиях эталона, рабочие публикации стенда не трогать. Коммиты как в публичный репо. Картинки печатей и подписей — только тестовые («ОБРАЗЕЦ»), не в репо.
- Каждую часть — снимки в журнал и «готово к приёмке» Славе.
