Порядок вкладок после v0.2: **Базы 1С · MCP · Доступ · Печатные формы · Журнал · Сервис · О программе**.

## Изменение 18.10.2026 — запись только по белому списку ([0013](/decisions/0013-belyj-spisok-zapisi))

Слава по снимку вкладки: «О программе» говорит «нет прав на запись», а «Доступ» даёт галочку «Запись» на всё — противоречие. Решение:

- **Колонка «Запись» активна только у белого списка** (в коде, не в конфиге, + тест): **Счёт на оплату покупателю, Доверенность, Акт сверки взаиморасчётов, Контрагенты, Банковские счета (контрагентов), Договоры контрагентов**. У остальных объектов вместо галочки записи — **замок** с подсказкой: «Bilem не создаёт документы, которые меняют бухгалтерский учёт. Нужно — напишите нам (Сервис → GitHub)». Раздел без объектов белого списка — замок и в строке раздела.
- По умолчанию запись выключена и для белого списка; включает пользователь (пароль администратора 1С + проверка — как описано ниже).
- Счётчики: «чтение 12 из 12 · запись 0 из 1» — «из» считает только то, что можно включить.
- Над деревом одна строка-обещание (то же — на «О программе», в README и на сайте): **«Bilem не меняет ваш бухгалтерский учёт: читает данные и готовит только счета, доверенности, акты сверки и карточки контрагентов — после вашего подтверждения, непроведёнными.»** Текст «О программе» про «нет прав на запись» заменить на это.
- Сценарий v0.3, под который это делается: «вот реквизиты (фото/текст) — заведи и выставь счёт» → поиск контрагента по БИН/ИИН (с проверкой контрольной суммы) → если нет — черновик контрагента (+ банковский счёт, договор) → «Подтвердить» → черновик счёта → «Подтвердить» → PDF.

Снимок текущей вкладки (дерево по разделам 1С, «Облако» у зарплаты и «Доступ по людям») — принят, дальше — только это изменение.

## Часть 1 — вкладка «Доступ» (было «Доступ к данным»)

### Что видит пользователь

- Сверху — выбор базы (как сейчас) и строка состояния: «Запись запрещена — проверено ДД.ММ ЧЧ:ММ» или «Запись разрешена: 3 объекта — проверено …».
- Главное — **дерево с двумя колонками-галочками «Чтение» и «Запись»**. Разделы сворачиваются; галочка на разделе ставит/снимает все объекты раздела, при частичном выборе — третье состояние (квадратик). Запись без чтения невозможна: галочка «Запись» ставит и «Чтение», снятие «Чтения» снимает и «Запись». Запись — только белый список (см. выше).
- У объектов — **человеческие имена** (синоним из метаданных 1С), техническое имя — в подсказке.
- Внизу — «Применить» и «Отменить»; до применения — сводка «что изменится».

### Разделы — как в левом меню 1С

Разделы берём **из подсистем самой конфигурации** (`Метаданные.Подсистемы` → состав, через помощник COM при настройке). Объект в нескольких подсистемах — в основной по профилю, остальное — «Прочее». Если подсистем нет — запасная раскладка из профиля:

| Раздел | Что внутри (БП КЗ) |
| --- | --- |
| Организация и справочники | организации, подразделения, валюты и курсы, банки, единицы, ставки НДС |
| Контрагенты и договоры | контрагенты, договоры, акт сверки, корректировка долга, доверенность |
| Банк и касса | банковские счета, кассы, статьи ДДС, платёжные поручения и ордера, ПКО/РКО, оплата картой |
| Продажа | счета покупателям, реализация, возвраты от покупателей, счета-фактуры выданные, чеки ККМ, отчёт о розничных продажах |
| Покупка | поступление, доп. расходы, возврат поставщику, счета-фактуры полученные |
| Номенклатура и склад | номенклатура и группы, склады, типы цен, цены, перемещение, списание, оприходование |
| Бухгалтерский учёт | план счетов и регистр бухгалтерии «Типовой» (только чтение; проводки по зарплате наружу не отдаются — правило MCP) |
| Зарплата и кадры | **закрытый раздел**: замок, галочки недоступны, метка «Облако» |
| Прочее | всё, что не попало в разделы |

### Что делают галочки при «Применить»

| Изменение | Слой MCP (сразу) | Слой 1С (нужен пароль администратора 1С) |
| --- | --- | --- |
| Чтение снято | инструменты больше не видят объект | убрать из состава OData |
| Чтение поставлено | объект доступен инструментам | добавить в состав OData + роль чтения, если текущих ролей не хватает |
| Запись поставлена (только белый список) | объект доступен для черновиков (инструменты записи — v0.3) | добавить `bilem` роль «ДобавлениеИзменение…» для этого объекта (минимальный набор по `ПравоДоступа`) |
| Запись снята | инструменты записи для объекта выключены | убрать роль, если она больше ни для чего не нужна |

- Изменения только слоя MCP применяются сразу. Если нужен слой 1С — окно «Логин и пароль администратора 1С» (не сохраняется), шаги с галочками и **автоматическая проверка** (чтение включённого, отказ в записи там, где запись выключена).
- Перед первым включением записи — предупреждение: «ИИ сможет готовить черновики этих документов. В 1С они попадут только после вашего подтверждения, непроведёнными».
- **Проведение и удаление не делаем никогда** ([0002](/decisions/0002-ne-trogaem-uchet)): вызовов `Post`, `Unpost`, `DELETE` и пометки на удаление в коде агента нет (тест).
- Изменения — в журнал: кто, когда, что включил/выключил.

### Что в платной версии — показываем, но не навязываем

Платные возможности видны **на своём естественном месте**, серыми, с меткой **«Облако»**, по щелчку — одна фраза «что это даст» + ссылка на лист ожидания. Без всплывающих окон и блокировок бесплатного. Блок «Доступ по людям · Облако»: разные права для разных людей и номеров; кто подтверждает документы, а кто только спрашивает; «Зарплата и кадры» — только тем, кому разрешили; ChatGPT, телефон, голос, WhatsApp/Telegram — вход по OAuth.

### Приёмка части 1

- Дерево по разделам 1С на v19, сворачивание, три состояния галочек, человеческие имена.
- Снять чтение раздела → MCP сразу не видит объекты, после «Применить» с паролем — их нет и в составе OData; вернуть — всё как было.
- **Запись:** у объектов вне белого списка — замок, включить нельзя (и через CLI тоже); включить запись для «Счёт на оплату покупателю» → у `bilem` нужная роль; проверка: POST счёта разрешён, POST реализации — отказ; тестовый счёт удалить под администратором. Выключить — снова «запись запрещена».
- Строка-обещание над деревом и на «О программе» — одинаковая; снимки в журнал.

## Часть 2 — вкладка «Печатные формы»

**Цель на сегодня:** спросить ИИ «дай счёт на оплату № …» → получить PDF с логотипом, печатью и подписью этой базы. Счёт **уже есть в 1С** — только чтение и печать, запись черновиков — v0.3.

### Вкладка (настройки — на каждую базу)

- Выбор базы. Всё ниже — **своё у каждой базы** (разные юрлица); кнопка «Скопировать из другой базы…».
- Три **плейсхолдера с превью**: «Логотип», «Печать», «Подпись (факсимиле)» — «Загрузить…», «Убрать». Лимиты (больше — агент сам ужимает, сообщая об этом):
  - логотип — PNG/JPG до 200 КБ, до 1000×400 px, в документе вписывается в 40×15 мм;
  - печать — PNG с прозрачным фоном до 200 КБ, круг около 40 мм;
  - подпись — PNG с прозрачным фоном до 100 КБ, около 40×15 мм;
  - файлы — в `C:\ProgramData\Bilem\bases\<имя>\print\` (только Администраторы и SYSTEM).
- **Подписант:** ФИО и должность (по умолчанию «Бухгалтер») — в OData физлиц нет.
- **Текст в шапке счёта** — с текстом по умолчанию, можно править; **Кбе и КНП** по умолчанию (17 / 710), если в базе не нашлись.
- «Формы»: **Счёт на оплату** (работает), Доверенность, Акт сверки — серые «скоро».
- Кнопка **«Пробный счёт…»**: выбрать счёт из 1С (последние 20 или по номеру) → PDF в просмотрщике Windows.

### PDF

- **PDFsharp + MigraDoc** (MIT, net48). Не QuestPDF — двойная коммерческая лицензия ([0012](/decisions/0012-podpis-koda)).
- Шрифт — встроенный, с кириллицей и казахскими буквами (ә ғ қ ң ө ұ ү һ і), открытая лицензия (PT Sans / Noto Sans, OFL).
- Макет — как печатная форма 1С и образец Куры: логотип + текст в шапке; «Образец платёжного поручения» (бенефициар, БИН, ИИК, Кбе, банк, БИК, КНП); «Счёт на оплату № … от …» (дата прописью); поставщик, покупатель, договор; таблица № / код / наименование / кол-во / ед. / цена / сумма; итого; **НДС** («В том числе НДС 12%» или «Без НДС»); сумма прописью (тенге/тиын); исполнитель, подпись и печать поверх строки подписи.
- Не повторить огрехи образца: «Ед.» не переносится по буквам, длинное имя бенефициара не налезает на БИН, «Кбе»/«КНП» не налезают на значения.
- Источники полей: счёт + табличная часть, организация, банковский счёт из счёта (иначе основной), банк, контрагент, договор, номенклатура и единицы; в строке — «Содержание», если заполнено, иначе наименование номенклатуры.

### MCP

- **`print_invoice`** (`base`, `number` или `last`): PDF в `Документы\Bilem\Счета\`, возвращает путь + сумму и покупателя. Имя файла: `Счёт №<номер> от <дата> — <покупатель>.pdf`.
- Приёмка: «сделай PDF счёта № …» → один вызов, файл открывается; суммы и реквизиты = печатная форма 1С того же счёта; логотип/печать/подпись — именно этой базы (две базы с разными картинками). PDF и данные — Славе в чат, не в журнал и не в репо.

## Правила

- На копиях эталона, рабочие публикации стенда не трогать. Коммиты как в публичный репо. Картинки печатей и подписей — только тестовые («ОБРАЗЕЦ»), не в репо.
- Каждую часть — снимки в журнал и «готово к приёмке» Славе.
