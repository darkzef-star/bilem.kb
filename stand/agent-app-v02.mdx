## Приёмка PDF, 18.10.2026 — замечания Славы (сделать сейчас)

Проверено: Claude Code на Маке Славы через Tailscale (`https://bakanof.<tailnet>.ts.net:8796`, `tailscale serve`) → `print_invoice` → PDF. Макет в целом принят: шапка, образец платёжки, таблица, «Без НДС», сумма прописью — в порядке.

<Steps>
  <Step title="1. Печать — на место">
    Сейчас печать стоит отдельно справа, далеко от подписи. Нужно **как в живом документе**: круг печати ставится **поверх строки «Исполнитель \_\_\_\_\_\_ /Бухгалтер/»**, левым краем — примерно на конец линии подписи, перекрывая «/Бухгалтер/» и частично саму подпись (Слава отметил место красной рамкой на снимке). Центр печати — по вертикали на уровне строки подписи или чуть ниже. Подпись — над линией, как сейчас. Положение — в мм от строки подписи (не от края листа), чтобы при длинной таблице печать ехала вместе со строкой. Снимок PDF — в журнал (данные в журнал не выкладывать: снимок только Славе в чат).
  </Step>
  <Step title="2. PDF — сразу из MCP">
    Сейчас `print_invoice` отдаёт только путь на стенде — клиент на другой машине (Мак через Tailscale, Claude Desktop) файла не получает. В ответе инструмента дополнительно:

    - **сам PDF** — ресурс MCP (`type: "resource"`, `mimeType: "application/pdf"`, `blob` — base64), имя файла в `uri`/`name`;
    - **картинка первой страницы** — `type: "image"`, PNG ~1000 px по ширине (для клиентов, которые не показывают PDF);
    - текст — как сейчас (номер, дата, покупатель, сумма, путь на стенде). Проверить в Claude Code на Маке через Tailscale: Claude сохраняет PDF у себя и/или показывает превью; в Claude Desktop. Если какой-то клиент ресурс не принимает — записать в журнал, какой и что видит. Размер ответа — PDF ~100–300 КБ, это нормально.
  </Step>
  <Step title="3. «Последний» — по дате">
    `last` — последний счёт **по дате**, при одинаковой дате — по номеру. (В учебной базе последний действительно 2022 года — она архивная; но правило нужно для живых баз.)
  </Step>
</Steps>

## Изменение 18.10.2026 — запись только по белому списку ([0013](/decisions/0013-belyj-spisok-zapisi))

Слава по снимку вкладки: «О программе» говорит «нет прав на запись», а «Доступ» даёт галочку «Запись» на всё — противоречие. Решение:

- **Колонка «Запись» активна только у белого списка** (в коде, не в конфиге, + тест): **Счёт на оплату покупателю, Доверенность, Акт сверки взаиморасчётов, Контрагенты, Банковские счета (контрагентов), Договоры контрагентов**. У остальных объектов вместо галочки записи — **замок** с подсказкой: «Bilem не создаёт документы, которые меняют бухгалтерский учёт. Нужно — напишите нам (Сервис → GitHub)». Раздел без объектов белого списка — замок и в строке раздела.
- По умолчанию запись выключена и для белого списка; включает пользователь (пароль администратора 1С + проверка — как описано ниже).
- Счётчики: «чтение 12 из 12 · запись 0 из 1» — «из» считает только то, что можно включить.
- Над деревом одна строка-обещание (то же — на «О программе», в README и на сайте): **«Bilem не меняет ваш бухгалтерский учёт: читает данные и готовит только счета, доверенности, акты сверки и карточки контрагентов — после вашего подтверждения, непроведёнными.»**
- Сценарий v0.3: «вот реквизиты — заведи и выставь счёт» → поиск по БИН/ИИН → черновик контрагента → «Подтвердить» → черновик счёта → «Подтвердить» → PDF.

## Часть 1 — вкладка «Доступ» (было «Доступ к данным»)

### Что видит пользователь

- Сверху — выбор базы и строка состояния: «Запись запрещена — проверено ДД.ММ ЧЧ:ММ» или «Запись разрешена: 3 объекта — проверено …».
- **Дерево с двумя колонками-галочками «Чтение» и «Запись»**: разделы сворачиваются; галочка на разделе ставит/снимает все объекты, при частичном выборе — третье состояние. Запись ставит чтение, снятие чтения снимает запись. Запись — только белый список.
- **Человеческие имена** (синоним из метаданных 1С), техническое имя — в подсказке.
- «Применить» / «Отменить»; до применения — сводка «что изменится».

### Разделы — как в левом меню 1С

Из подсистем самой конфигурации (`Метаданные.Подсистемы`); объект в нескольких — в основной по профилю, остальное — «Прочее»; если подсистем нет — запасная раскладка (Организация и справочники; Контрагенты и договоры; Банк и касса; Продажа; Покупка; Номенклатура и склад; Бухгалтерский учёт — только чтение; Зарплата и кадры — закрыт, замок, «Облако»; Прочее).

### Что делают галочки при «Применить»

| Изменение | Слой MCP (сразу) | Слой 1С (пароль администратора 1С) |
| --- | --- | --- |
| Чтение снято | инструменты не видят объект | убрать из состава OData |
| Чтение поставлено | объект доступен инструментам | добавить в состав OData + роль чтения при необходимости |
| Запись поставлена (белый список) | объект доступен для черновиков (v0.3) | роль «ДобавлениеИзменение…» по `ПравоДоступа` (минимальная) |
| Запись снята | запись выключена | убрать роль, если больше не нужна |

- Проведение и удаление — никогда ([0002](/decisions/0002-ne-trogaem-uchet)); вызовов `Post`, `Unpost`, `DELETE` в коде нет (тест). Изменения — в журнал.

### Платное — показываем, не навязываем

Метка **«Облако»** на своём месте, по щелчку — фраза и ссылка на лист ожидания. Блок «Доступ по людям · Облако».

## Часть 2 — вкладка «Печатные формы»

**Цель:** спросить ИИ «дай счёт на оплату № …» → PDF с логотипом, печатью и подписью этой базы. Счёт уже есть в 1С — только чтение и печать; черновики — v0.3.

### Вкладка (на каждую базу)

- Выбор базы; «Скопировать из другой базы…».
- Плейсхолдеры с превью: «Логотип», «Печать», «Подпись (факсимиле)» — «Загрузить…», «Убрать». Лимиты: логотип PNG/JPG ≤ 200 КБ, ≤ 1000×400 px (в документе 40×15 мм); печать PNG прозрачный ≤ 200 КБ (круг ~40 мм); подпись PNG прозрачный ≤ 100 КБ (~40×15 мм). Файлы — `C:\ProgramData\Bilem\bases\<имя>\print\` (только Администраторы и SYSTEM).
- Подписант (ФИО, должность), текст в шапке, Кбе/КНП по умолчанию.
- «Формы»: Счёт на оплату (работает), Доверенность, Акт сверки — «скоро». «Пробный счёт…».

### PDF

PDFsharp + MigraDoc (MIT), шрифт PT Sans (OFL, казахские буквы). Макет как печатная форма 1С и образец Куры; огрехи образца исправлены; источники полей — счёт, организация, банк. счёт (иначе основной), банк, контрагент, договор, номенклатура; в строке — «Содержание», иначе наименование.

### MCP

`print_invoice` (`base`, `number` или `last`) → PDF в `Документы\Bilem\Счета\` + **(новое) сам PDF и превью в ответе** — см. «Приёмка PDF» сверху.

## Правила

- На копиях эталона, рабочие публикации стенда не трогать. Коммиты как в публичный репо. Картинки печатей и подписей — только тестовые («ОБРАЗЕЦ»), не в репо.
- Каждую часть — снимки в журнал и «готово к приёмке» Славе.
