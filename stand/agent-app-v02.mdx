## Приёмка PDF, 18.10.2026 — замечания Славы (сделать сейчас)

Проверено: Claude Code на Маке Славы через Tailscale (`https://bakanof.<tailnet>.ts.net:8796`, `tailscale serve`) → `print_invoice` → PDF. Макет в целом принят: шапка, образец платёжки, таблица, «Без НДС», сумма прописью — в порядке.

<Steps>
  <Step title="1. Печать — на место">
    Сейчас печать стоит отдельно справа, далеко от подписи. Нужно **как в живом документе**: круг печати ставится **поверх строки «Исполнитель \_\_\_\_\_\_ /Бухгалтер/»**, левым краем — примерно на конец линии подписи, перекрывая «/Бухгалтер/» и частично саму подпись (Слава отметил место красной рамкой на снимке). Центр печати — по вертикали на уровне строки подписи или чуть ниже. Подпись — над линией, как сейчас. Положение — в мм от строки подписи (не от края листа), чтобы при длинной таблице печать ехала вместе со строкой. Снимок PDF — только Славе в чат (данные в журнал не выкладывать).
  </Step>
  <Step title="2. PDF — сразу из MCP">
    Сейчас `print_invoice` отдаёт только путь на стенде — клиент на другой машине (Мак через Tailscale, Claude Desktop) файла не получает. В ответе инструмента дополнительно:

    - **сам PDF** — ресурс MCP (`type: "resource"`, `mimeType: "application/pdf"`, `blob` — base64), имя файла в `uri`/`name`;
    - **картинка первой страницы** — `type: "image"`, PNG ~1000 px по ширине (для клиентов, которые не показывают PDF);
    - текст — как сейчас (номер, дата, покупатель, сумма, путь на стенде).

    Проверить в Claude Code на Маке через Tailscale: Claude сохраняет PDF у себя и/или показывает превью; в Claude Desktop. Если какой-то клиент ресурс не принимает — записать в журнал, какой и что видит. Размер ответа — PDF ~100–300 КБ, это нормально.
  </Step>
  <Step title="3. «Последний» — по дате">
    `last` — последний счёт **по дате**, при одинаковой дате — по номеру. (В учебной базе последний действительно 2022 года — она архивная; но правило нужно для живых баз.)
  </Step>
  <Step title="4. Папки — по базам и видам документов">
    Документы раскладываются так: **`Документы\Bilem\<имя базы>\<вид документа>\`** — например `Документы\Bilem\v21\Счета\`, `…\v21\Доверенности\`, `…\v21\Акты сверки\`. Имя базы — короткое имя из агента (сейчас v19, v20, v21 — так и оставляем). Папки вида создаются при первом документе этого вида. Имя файла — как сейчас: `Счёт №<номер> от <дата> — <покупатель>.pdf`. Старые файлы из `Документы\Bilem\Счета\` — перенести в новую раскладку при первом запуске (или оставить с записью в журнал, если перенос не удался).
  </Step>
</Steps>

## Изменение 18.10.2026 — запись только по белому списку ([0013](/decisions/0013-belyj-spisok-zapisi))

- **Колонка «Запись» активна только у белого списка** (в коде, не в конфиге, + тест): **Счёт на оплату покупателю, Доверенность, Акт сверки взаиморасчётов, Контрагенты, Банковские счета (контрагентов), Договоры контрагентов**. У остальных — **замок** с подсказкой «Bilem не создаёт документы, которые меняют бухгалтерский учёт. Нужно — напишите нам (Сервис → GitHub)».
- По умолчанию запись выключена и для белого списка. Счётчики «запись 0 из N» — только то, что можно включить.
- Строка-обещание над деревом, на «О программе», в README и на сайте: **«Bilem не меняет ваш бухгалтерский учёт: читает данные и готовит только счета, доверенности, акты сверки и карточки контрагентов — после вашего подтверждения, непроведёнными.»**

## Часть 1 — вкладка «Доступ» (было «Доступ к данным»)

- Выбор базы, строка состояния «Запись запрещена — проверено …».
- Дерево разделов 1С (из подсистем конфигурации; запасная раскладка из профиля) с колонками «Чтение» / «Запись», три состояния галочек, человеческие имена (синонимы), «Применить» / «Отменить» со сводкой.
- «Применить»: слой MCP — сразу; слой 1С — с паролем администратора (состав OData, роли по `ПравоДоступа`), автоматическая проверка.
- Проведение и удаление — никогда ([0002](/decisions/0002-ne-trogaem-uchet)), тест. Изменения — в журнал.
- Платное — метка «Облако» на своём месте; блок «Доступ по людям · Облако».

## Часть 2 — вкладка «Печатные формы»

**Цель:** спросить ИИ «дай счёт на оплату № …» → PDF с логотипом, печатью и подписью этой базы. Счёт уже есть в 1С — только чтение и печать; черновики — v0.3.

- Вкладка на каждую базу: «Скопировать из другой базы…»; плейсхолдеры «Логотип», «Печать», «Подпись (факсимиле)» с лимитами (логотип ≤ 200 КБ, ≤ 1000×400 px; печать PNG прозрачный ≤ 200 КБ; подпись PNG прозрачный ≤ 100 КБ), файлы — `C:\ProgramData\Bilem\bases\<имя>\print\` (только Администраторы и SYSTEM); подписант, текст в шапке, Кбе/КНП; «Формы» (Счёт — работает; Доверенность, Акт сверки — «скоро»); «Пробный счёт…».
- PDF: PDFsharp + MigraDoc (MIT), PT Sans (OFL, казахские буквы), макет как печатная форма 1С; огрехи образца исправлены.
- MCP: `print_invoice` (`base`, `number` или `last`) → PDF в `Документы\Bilem\<база>\Счета\` + сам PDF и превью в ответе (см. «Приёмка PDF» сверху).

## Правила

- На копиях эталона, рабочие публикации стенда не трогать. Коммиты как в публичный репо. Картинки печатей и подписей — только тестовые («ОБРАЗЕЦ»), не в репо.
- Каждую часть — снимки в журнал и «готово к приёмке» Славе.
