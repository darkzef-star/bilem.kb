## 18.10.2026 · Замечания по приёмке PDF — сделаны

<Check>
  Коммит **`f2887fc`**, CI зелёный — прогон 39125189576, 2 мин 1 с, тесты **104 из 104**. Через MCP на стенде: ответ 320 КБ за 0,8 с — текст + PDF (130 КБ, ресурс) + PNG первой страницы (110 КБ).
</Check>

1. **Печать — на месте**: левым краем — на конце линии подписи (−8 мм), поверх «/Бухгалтер/», центр — на 3 мм ниже середины строки подписи. Отступы считаются от строки подписи по её положению на странице и ширине текста «Исполнитель \_\_\_», поэтому печать едет вместе со строкой при длинной таблице. Подпись — над линией, как была. Снимок — Славе.
2. **PDF — в ответе MCP**: `content` = текст (номер, дата, покупатель, сумма, путь, имя файла) + `{"type":"resource","resource":{"uri":"file:///…","name":"Счёт №….pdf","mimeType":"application/pdf","blob":"<base64>"}}` + `{"type":"image","mimeType":"image/png","data":"<base64>"}` (1000 px по ширине). Превью — встроенный рендер Windows `Windows.Data.Pdf` (пакет `Microsoft.Windows.SDK.Contracts` 10.0.19041.1 — только ссылочные метаданные, нативных библиотек нет); нет рендера (старая Windows) — PDF уходит без картинки, в журнал — предупреждение. Тест — дополнительное содержимое идёт после текста.
3. **«Последний»** — `$orderby=Date desc,Number desc`.
4. **Папки**: `Документы\Bilem\<база>\Счета\` (создаётся при первом документе). Старая `Документы\Bilem\Счета\`: база одна — файлы переносятся; баз несколько (как на стенде: v19, v20) — по имени файла базу не определить, **папка оставлена как есть** (4 файла), в журнале агента — предупреждение.

**Проверить Славе на Маке**: Claude Code через Tailscale и Claude Desktop — сохраняет ли PDF из ресурса, показывает ли превью. На стенде (сырой ответ MCP) — ресурс и картинка приходят, PDF из `blob` открывается.

**Процесс**: проверка перед push в этот раз совпала на `Version="10.0.19041.1"` (номер версии пакета похож на адрес 10.\*), а коммит прошёл — цепочка команд не остановилась на совпадении. Утечки нет (это версия), но правило нарушено; дальше проверка — отдельным шагом до коммита.

### Что сделано

- **PDF счёта на оплату** (счёт уже есть в 1С — только чтение): макет печатной формы 1С и образца Славы — шапка с логотипом и текстом, «Образец платежного поручения» (бенефициар, БИН, ИИК, Кбе, банк, БИК, КНП), «Счёт на оплату № … от …» (дата прописью), поставщик (с юр. адресом), покупатель, договор, таблица, итого, НДС («в том числе» / «Без НДС»), сумма прописью (тенге/тиын), исполнитель; **подпись и печать — поверх строки подписи** по её месту на странице.
- **Огрехи образца исправлены**: «Ед.» в одну строку (длинная единица — меньшим кеглем, не по буквам); длинное имя бенефициара переносится внутри своей ячейки и не налезает на БИН; «Кбе», «Код назначения платежа» — в своих ячейках над значениями.
- Источники: счёт + товары и услуги (в строке — «Содержание», иначе номенклатура), организация (полное имя, БИН, Кбе, основной банковский счёт → банк, БИК), контрагент, договор, единицы, ставки НДС. Юр. адреса в составе OData нет (там и данные физлиц) — берётся помощником COM «Реквизиты из 1С…» (только организации, только адрес) и хранится в настройках печати базы.
- Номер — как на печати в 1С («00-000004» → «4»); найти можно по любому из двух.
- **PDFsharp + MigraDoc 6.2.4** (MIT; 6.5.0 — моложе двух недель, не брал), шрифт **PT Sans** (OFL, `assets/fonts` + текст лицензии): все казахские буквы есть (проверено по таблице глифов); знака ₸ в шрифте нет — пишем «тенге», как в образце.
- **Вкладка «Печатные формы»** (после «Доступа»): база, «Скопировать из другой базы…», три превью «Логотип / Печать / Подпись (факсимиле)» — «Загрузить…» / «Убрать» (больше лимита — ужимаем и говорим), подписант и должность, Кбе/КНП, текст шапки, адреса из 1С, «Формы: Счёт на оплату — работает; Доверенность, Акт сверки — скоро», «Пробный счёт…» (последние 20 счетов или номер → PDF в просмотрщике). Картинки — `C:\ProgramData\Bilem\bases\<имя>\print`, права только Администраторам и SYSTEM.
- **MCP `print_invoice`** (`base`, `number` или `last`) → PDF в «Документы\\Bilem\\Счета», имя «Счёт №4 от 13.04.2022 — ТОО ….pdf»; ответ — путь, покупатель, сумма. Слой «Доступа» действует и здесь: выключенный объект — отказ до запроса.
- Команда `bilem-agent print --slug … [--number …]`.
- Картинки на стенде — только тестовые «ОБРАЗЕЦ» (нарисованы скриптом, вне репо).

## 18.10.2026 · Часть 1 «Доступ» — готово к приёмке

<Check>
  Коммит **`cb818f7`**, CI зелёный — прогон 39098283008, 1 мин 39 с, тесты **84 из 84** (новые — 8 на «Доступ», среди них «в коде нет проведения, отмены проведения и удаления»). Приёмка Земли на копии v19 — все пункты ТЗ прошли.
</Check>

### Что сделано

- **Разделы — из подсистем самой конфигурации** (помощник COM `metaCatalog`, только метаданные): на v19 — 10 разделов, 52 объекта: Банк и касса, Продажа, Покупка, Номенклатура и склад, Производство, ОС и НМА, Операции, Предприятие, **Зарплата и кадры** (замок), Прочее. Порядок — как в меню 1С; служебные подсистемы (Администрирование, Отчёты, Руководителю) разделом не становятся. Объект в нескольких подсистемах — по профилю: контрагенты и договоры → «Предприятие» (это и есть «справочники и настройки» БП КЗ), остальное — первый раздел по порядку меню.
- **Имена — синонимы из метаданных** («Счет на оплату покупателю», «Платежное поручение (входящее)»), техническое имя — в подсказке. До загрузки разделов (базы, подключённые в v0.1) — запасная раскладка из таблицы ТЗ; загрузить — ссылка «Разделы из 1С…» (вход администратора, в базе ничего не меняется). При новой настройке разделы грузятся сами.
- **Галочки**: две колонки «Чтение / Запись», у раздела — три состояния и счётчик «чтение 5 из 7 · запись 0». Запись ставит чтение, снятие чтения снимает запись. Запись — только у справочников и документов (регистры и план счетов — только чтение). Внизу — сводка «что изменится», «Применить» / «Отменить».
- **«Применить»**: слой MCP — сразу (инструмент на выключенный объект отвечает «Объект «Контрагенты» в базе v19 выключен на вкладке «Доступ»…», в 1С запрос не уходит); слой 1С — с паролем администратора (не сохраняется): роли bilem, состав OData ровно по чтению, автоматическая проверка. Отказался от пароля — для ИИ уже действует, в 1С — при следующем «Применить».
- **Подбор роли записи** — по `ПравоДоступа`: самая узкая (меньше всего объектов с добавлением); «Полные права», роли администрирования и устаревшие «Удалить…» не выбираются никогда. Для «Счёта на оплату покупателю» — `ДобавлениеИзменениеСчетовПокупателям` (запись на 1 объект из 52; у `ДобавлениеИзменениеДанныхБухгалтерии` — 44).
- Перед первым включением записи — предупреждение из ТЗ. Изменения — в журнал: кто, когда, сколько, какие объекты.
- **Проверка после «Применить»**: запрет записи — на объектах, где запись выключена (раньше POST шёл всегда в счёт на оплату — при включённой записи создал бы пустой документ); выключенные объекты не видны в `$metadata`.
- Повторная настройка базы «Доступ» не сбрасывает; MCP перечитывает config.json при изменении (окно и командная строка). Команда `bilem-agent access --slug … [--load] [--read-on|--read-off|--write-on|--write-off …] [--admin …]`.
- **Облако**: блок «Доступ по людям · Облако» под деревом (по щелчку — четыре пункта из ТЗ и ссылка на лист ожидания), метка «Облако» у замка «Зарплаты и кадров» и в блоке облака на вкладке «MCP».
- **Шрифт** — везде обычный, без жирного (замечание Славы, принято).
- Вкладка называется «Доступ».

### Что посмотреть руками

1. «Доступ» → v19: раскрыть раздел, снять/поставить галочку объекта и раздела — сводка «Изменится: …»; «Отменить».
2. Щёлкнуть «Доступ по людям» или замок «Зарплаты и кадров» — пункты облака и ссылка на лист ожидания (снимок в раскрытом виде не сделал: окном в это время пользовался Слава).
3. v20 — разделы ещё по запасной раскладке: «Разделы из 1С…» → логин администратора → разделы как в 1С.
4. Включить запись у объекта — предупреждение, затем пароль администратора и шаги с проверкой.
