cfe публикуется от пользователя `bilem`. Платформа сама проверяет права — расширение не может больше, чем разрешено пользователю. Всё настраивается **в пользовательском режиме 1С**, без Конфигуратора. Решение — [0006](/decisions/0006-prava-v-1c).

<Warning>
  `УстановитьПривилегированныйРежим` в коде расширения не используется. Иначе роли бессмысленны.
</Warning>

## Слой 1 · Роли по разделам

| Роль | Что даёт | Инструменты |
| --- | --- | --- |
| `Bilem_Справочники` | организация, контрагенты, договоры, номенклатура | `org`, `counterparty*`, `contracts`, `nomenclature_find`, `price_list` |
| `Bilem_Деньги` | счета, кассы, движение денег | `balance`, `cash_flow`, `bank_statement`, `cash_book` |
| `Bilem_Расчеты` | дебиторка, кредиторка, авансы, сальдо | `debtors`, `creditors`, `counterparty_balance`, `unpaid_invoices`, `received_unpaid`, `advances` |
| `Bilem_Продажи` | выручка, документы продаж | `sales*`, `invoice_status`, `documents_find` |
| `Bilem_Склад` | остатки, закупки | `stock`, `stock_item`, `purchases` |
| `Bilem_Налоги` | налоги, ЭСФ, НДС | `taxes_due`, `tax_calendar`, `vat_summary`, `esf_status` |
| `Bilem_Зарплата` | ФОТ и численность без ФИО | `headcount`, `payroll_total`, `salary_debt` |
| `Bilem_Отчеты` | ОСВ, обороты, P&L, ОС | `osv`, `account_turnover`, `pnl`, `fixed_assets`, `document` |
| `Bilem_ВыпискаСчетов` | счёт на оплату без проведения | `invoice_create` |
| `Bilem_АктыСверки` | акт сверки | `reconciliation_create` |
| `Bilem_Доверенности` | доверенность, непроведённая реализация | `power_of_attorney_create`, `realization_draft` |
| `Bilem_Почта` | отправка писем через учётную запись 1С | `send_email` |
| `Bilem_Администратор` | менять политику инструментов — **не для пользователя bilem** | — |

Служебные `tools`, `health`, `print` доступны при любой из ролей. ~~Bilem_Запись~~ — нет и не будет ([0002](/decisions/0002-ne-trogaem-uchet)).

**Профиль групп доступа БСП «Bilem — агент»** поставляется в cfe со всеми ролями, кроме `Bilem_Администратор`. Администратор клиента снимает галки с ненужных ролей — платформа перестаёт отдавать эти данные. Штатное ограничение на уровне записей (например, одна организация из нескольких) работает поверх.

## Слой 2 · Политика инструментов

Регистр сведений `BilemПолитикаИнструментов`: инструмент → включён/выключен + параметры. Форма — вкладка «Инструменты» в «Подключение Bilem».

| Пример | Как настраивается |
| --- | --- |
| Акты сверки не формировать | `reconciliation_create` — выключить |
| Дебиторка без сумм по контрагентам | `debtors` — параметр «только итог» |
| Выручка не глубже года | `sales` — параметр «глубина, мес» = 12 |
| Письма только с подтверждением | `send_email` — параметр «подтверждение» |

- Отключённый инструмент не попадает в `tools/list` — агент о нём не знает.
- Прямой вызов → `403 {"error":"forbidden","reason":"disabled_by_admin"}`.
- Менять политику может только `Bilem_Администратор`; изменения — в журнале регистрации.

## Как агент решает, что можно

Инструмент доступен, только если:

1. есть роль у пользователя `bilem` в 1С (слой 1);
2. инструмент включён в политике (слой 2);
3. включён тарифом.

**Облако Bilem проверяет только белый список** — кто может писать агенту. Разделения «бухгалтеру можно, менеджеру нельзя» в облаке нет: все из белого списка получают ровно то, что разрешено пользователю `bilem`. Кому нужно разное — разные пользователи-агенты в 1С (позже, по спросу).

`GET /org` отдаёт фактически действующие роли и политику — агент и кабинет видят то же, что настроено в 1С.

## Лицензия 1С

HTTP-сервис = сеанс 1С. На время запроса занимается одна клиентская лицензия; сеанс живёт ~20 с и переиспользуется. Формулировка для клиента: «агенту нужна одна лицензия 1С».
