## Решение

| Когда | Чем подписываем | Издатель в Windows | Цена |
| --- | --- | --- | --- |
| Сейчас: пилоты (Зимин и др.) | без подписи, ставим сами («Подробнее → Выполнить в любом случае») | — | 0 |
| Открытый агент (репо открыт, первый релиз) — и дальше, пока клиент полностью открытый | **SignPath Foundation** — подпись open-source из GitHub Actions, ключ в их облачном HSM | SignPath Foundation | 0 |
| Если появится закрытая сборка или нужен свой бренд издателя | **OV-сертификат в облаке на ТОО** — Certum «Code Signing in the Cloud» (SimplySign); альтернативы — SSL.com eSigner, Sectigo | SKP.kz LLC | от ~€49 |

Параллельно: **D-U-N-S для ТОО** (бесплатно, 1–2 недели) → **Apple Developer на ТОО** ($99/год).

## Можно ли оставаться на SignPath и во время коммерции

Да, если платное остаётся **на нашей стороне** (облако `mcp.bilem.ai`, OAuth, каналы, поддержка), а программа у клиента — **целиком открытый код**, включая клиентскую часть облачного режима. Условия SignPath (signpath.org/terms), которые важны для нас:

- **Нет проприетарных компонентов и коммерческого двойного лицензирования** в подписываемой программе. Закрытые функции внутри exe → эту сборку SignPath подписывать нельзя, нужна своя OV.
- **Репутация проекта:** исполняемые программы подписывают проектам с проверяемой репутацией — нового проекта без пользователей могут не принять. План: первый релиз выходит без подписи, заявка — когда появятся звёзды и скачивания.
- **Приватность:** если данные уходят в системы, не указанные пользователем, — политика конфиденциальности при установке и возможность отключить. Облачный режим включается пользователем явно; политику всё равно публикуем.
- **Изменения системы — с предупреждением, и есть удаление:** у нас план «что поменяю» перед применением и команда `remove` — подходит.
- **Процесс:** MFA у всех в GitHub и SignPath; роли (авторы, ревьюеры, утверждающий релизы); каждый релиз утверждается вручную; сборка только из репо в CI; страница «Code signing policy» на сайте со строкой «Free code signing provided by SignPath.io, certificate by SignPath Foundation».
- **Риск:** издатель — SignPath Foundation, при нарушении правил они могут отозвать сертификат. Плюс: репутация SmartScreen у их сертификата уже накоплена.

## Почему

- Мгновенного доверия SmartScreen не даёт ни один сертификат, даже EV — репутация копится от скачиваний. Платить дорого за «чтобы не предупреждало» смысла нет.
- SignPath подходит open core ([0010](/decisions/0010-besplatno-bez-limitov)): MIT, публичный репо, бесплатные загрузки. Так подписаны Pandoc и другие известные проекты.
- Своё имя издателя нужно, только если появится закрытая сборка или крупные клиенты потребуют наш бренд; облачный ключ — чтобы подписывать из CI, а не с одной машины с USB-токеном.
- D-U-N-S нужен Apple для регистрации организации и ускоряет проверку у удостоверяющих центров.

## Что отвергли / отложили

- **Azure Artifact Signing** (~$10/мес) — только организации США/Канады/ЕС/UK, ТОО из КЗ не примут.
- **EV** — дороже, мгновенного доверия больше не даёт; нужен только для драйверов.
- **USB-токен** — ключ привязан к одной машине.

## Что из этого следует

- Слава: запросить D-U-N-S для ТОО (через страницу поиска D-U-N-S на сайте Apple Developer; не нашлось — там же заявка).
- Держать клиент полностью открытым — тогда хватает SignPath; любую закрытую функцию — только на сервер.
- К заявке в SignPath: страница «Code signing policy» на bilem.ai, политика конфиденциальности, роли в GitHub, MFA у всех.
- Свой OV (Certum) — по необходимости; проверка ТОО 2–3 недели; с марта 2026 срок сертификатов кода короче — продлевать чаще.
- Apple Developer нужен для «Sign in with Apple», приложения iPhone/Mac, подписи macOS. Для SSO в Enterprise (Okta, Azure AD, Google) — не нужен.
- Подробности и история — `docs/ideas/code-signing.md` в minidesk.
