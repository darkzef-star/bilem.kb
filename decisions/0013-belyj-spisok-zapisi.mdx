## Решение

В нашей сборке запись разрешена только для **белого списка** — объекты, которые **не дают проводок и не меняют бухгалтерский учёт**:

| Объект | Зачем |
| --- | --- |
| Счёт на оплату покупателю | главный сценарий: «выставь счёт», «как в прошлом месяце» |
| Доверенность | выписать на получение ТМЦ |
| Акт сверки взаиморасчётов | сверка с контрагентом |
| Контрагент | «вот реквизиты (фото/текст) — заведи и выставь счёт»; **сначала поиск по БИН/ИИН**, создаём, только если нет |
| Банковский счёт контрагента | реквизиты из того же фото |
| Договор контрагента | если счёту нужен договор |

- **Всё остальное — под замком**, включить нельзя: реализация, поступление, банк и касса, счета-фактуры (ЭСФ и НДС), склад, номенклатура, зарплата, проводки. Проведение и удаление — никогда ([0002](/decisions/0002-ne-trogaem-uchet)).
- **По умолчанию запись выключена и для белого списка** — клиент включает сам галочкой на вкладке «Доступ» (с паролем администратора 1С и проверкой).
- **Любая запись — черновик → кнопка «Подтвердить» мимо модели**; документы в 1С — непроведённые.
- Расширяем список только по запросу с легитимной причиной, если это не меняет учёт (решает Слава, совет — бухгалтеры). Форк с другим списком — ответственность того, кто его собрал.

## Почему

- Агент — помощник бухгалтера, не замена: он готовит документы «для людей» (счёт, доверенность, сверка), а учёт ведёт бухгалтер.
- Одно обещание клиенту во всех местах (сайт, README, «О программе», «Доступ»): **«Bilem не меняет ваш бухгалтерский учёт»** — и оно всегда правда.
- Убирает противоречие, которое заметил Слава: «О программе» говорит «нет прав на запись», а «Доступ» даёт галочку «Запись» на всё.

## Что отвергли

- Запись на любые объекты по выбору клиента (как у 1c-odata-mcp) — слишком легко испортить учёт и потерять доверие.
- Номенклатура — пока под замком (лишние позиции засоряют справочник и счета учёта); вернёмся с бухгалтерами.

## Что из этого следует

- [ТЗ v0.2](/stand/agent-app-v02), часть 1 «Доступ»: колонка «Запись» активна только у белого списка, у остальных — замок; тексты «О программе» и «Доступ» — одно обещание.
- Белый список — в коде (не в конфиге клиента) + тест; инструменты записи v0.3 не могут обратиться к объекту вне списка.
- Сценарий v0.3 «реквизиты → счёт»: ИИ распознаёт фото/текст → `find_counterparty` по БИН (проверка контрольной суммы) → если нет — черновик контрагента (+ счёт, договор) → «Подтвердить» → черновик счёта → «Подтвердить» → PDF.
