## Решение

- **Bilem Agent** — одна Windows-программа у клиента: подключается к базам 1С через **OData**, сама является **MCP-сервером**, держит периметр (белый список IP, токен, закрытые разделы), почта (SMTP), позже PDF.
- **Расширения (`cfe`) нет.** `bilem.cfe` заморожен как эталон для сверки «было = стало».
- **Публикация OData только на 127.0.0.1** — агент стоит на той же машине; снаружи OData не видна.
- Пользователь `bilem` создаётся автоматически через COM (`V83.COMConnector`) при вводе пароля администратора 1С; права — только чтение (роли, проверено); состав OData — минимальный.
- Два режима в одной программе: локально (бесплатно) и облако (платно, исходящее соединение к `mcp.bilem.ai`, OAuth) — облако позже.

## Почему

- Онбординг в три шага для ролика: установить → выбрать базу и ввести пароль админа → «Подключить к Claude/ChatGPT».
- Переживает обновления 1С: состав OData хранится в базе, расширение не «отваливается».
- Одна программа на любые конфигурации: профиль базы строится по `$metadata`.
- Практика: Куралай уже делает счета через OData в базе СКП без выдумок.
- Взвешенная оценка 17.10: OData + агент 143 из 180 против 111 у cfe.

## Что отвергли / отложили

- **cfe как основа** — ломается при обновлениях конфигурации, ветка на каждую конфигурацию, для облака всё равно нужна служба.
- **Гибрид «COM + тонкое расширение без публикации»** — рассмотрен, отложен.
- **PDF, печать, логотип** — отдельным модулем агента, не через 1С ([ТЗ v0.2](/stand/agent-app-v02)).
