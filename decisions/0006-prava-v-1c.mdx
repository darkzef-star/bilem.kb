## Решение

Клиент сам решает, что агенту можно, **в пользовательском режиме своей 1С**, без Конфигуратора и без доработки конфигурации под клиента. Для этого в cfe два слоя:

<Steps>
  <Step title="Слой 1 · Роли по разделам — технический потолок">
    Вместо двух ролей — набор по разделам каталога: `Bilem_Справочники`, `Bilem_Деньги`, `Bilem_Расчеты`, `Bilem_Продажи`, `Bilem_Склад`, `Bilem_Налоги`, `Bilem_Зарплата`, `Bilem_Отчеты`, `Bilem_ВыпискаСчетов`, `Bilem_АктыСверки`, `Bilem_Доверенности`, `Bilem_Почта` — полная таблица в [Ролях и правах](/cfe/roles). cfe поставляет готовый **профиль групп доступа БСП «Bilem — агент»**. Администратор клиента снимает галки с ненужных ролей у пользователя `bilem` — и платформа физически не даёт прочитать эти данные. Сюда же — штатное ограничение на уровне записей (например, только одна организация из нескольких).
  </Step>
  <Step title="Слой 2 · Политика инструментов — тонкая настройка">
    Регистр сведений `BilemПолитикаИнструментов`: инструмент → включён/выключен + параметры (глубина периода, скрыть суммы по контрагентам, отправка почты только с подтверждением). Отключённый инструмент не попадает в `tools/list` — агент о нём не знает. Прямой вызов → `403 {"error":"forbidden","reason":"disabled_by_admin"}`, в чате: «отключено администратором вашей 1С».
  </Step>
</Steps>

<Warning>
  Менять роли и политику может только администратор с ролью `Bilem_Администратор`. У пользователя `bilem` этой роли нет никогда — агент не может включить себе инструмент сам. Все изменения пишутся в журнал регистрации.
</Warning>

## Облако Bilem — только белые списки

На стороне Bilem настраивается одно: **кто может писать агенту** (белый список номеров и аккаунтов). Разграничения «бухгалтеру зарплату можно, менеджеру нельзя» в облаке **нет**.

- Почему: это ненадёжный слой — права должны жить там, где данные. Если человек в белом списке, он получает ровно то, что разрешено пользователю `bilem` в 1С.
- Кому нужно разное — заводят в 1С разных пользователей-агентов с разными ролями (позже, по спросу).
- Ролевую модель людей в облаке допишем, только если придёт крупный Enterprise с таким требованием.

## Почему так

- Ответ службе безопасности клиента: потолок задаёт платформа 1С, политику — администратор клиента, Bilem ничего не может выдать себе сам.
- Ни одной правки конфигурации под клиента — всё в пользовательском режиме.
- Права проверяет платформа, а не наш код — меньше места для ошибки.
