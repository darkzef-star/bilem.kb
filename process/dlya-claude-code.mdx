## Фокус сейчас

<Warning>
  **Только cfe.** Служба, облако, сертификаты — не сейчас. Задача — как можно больше методов HTTP-сервиса, каждый принят curl по контракту.
</Warning>

1. Собрать документацию 1С в `onec/` и подключить EDT-MCP (если Баканов выбрал EDT).
2. [bilem.cfe#1](https://github.com/skp-kz/bilem.cfe/issues/1) — полный каталог операций без вреда учёту.
3. Скелет: `GET /org`, `GET /tools`, `GET /health`, `POST /mcp` с одним инструментом `org`.
4. Дальше — методы по одному, порядок из каталога.

## Где что писать

| Что | Куда | Как |
|---|---|---|
| Задача, вопрос, обсуждение | GitHub issue в `bilem.cfe` | `gh issue comment N --body "…"` |
| Код | ветка `cfe/N-…` → PR с `Closes #N` | см. [Цикл задачи](/process/workflow) |
| Знание, которое пригодится снова | эта база, раздел `onec/` или `decisions/` | admin MCP `mcp.mintlify.com` или git в `skp-kz/bilem.kb` |
| Итоги встречи | `meetings/ГГГГ-ММ-ДД.mdx` | обычно пишет Кура из tl;dv |
| Журнал сессии | `bilem.cfe/docs/journal.md` | новые сверху |

<Tip>
  Правило: если ты что-то выяснил про 1С и это заняло больше 10 минут — запиши в `onec/`. Следующий агент не будет искать заново.
</Tip>

## Подключения

```powershell
claude mcp add --transport http mintlify https://mcp.mintlify.com   # эта база: читать и писать
gh auth status                                                       # GitHub: issues, PR, доска
```

MCP самой cfe (`bilem`) — в `.mcp.json` репо `bilem.cfe`, заработает после публикации базы и токена.

## Чего не делать

- Не проводить документы, не создавать платёжки, не использовать привилегированный режим.
- Не класть в базу и в git пароли, токены, данные реальных клиентов.
- Не менять контракт `cfe/spec` молча — только через issue и согласие Славы.
