**Репо:** `skp-kz/bilem.agent` · **Видимость:** закрытый сейчас, потом откроем **как есть, со всей историей** · **Решение Славы:** 18.10.2026

Bilem Agent — Windows-программа: 1С (OData на 127.0.0.1) → MCP-сервер для ИИ. Почему так — [0009 · OData + Bilem Agent вместо cfe](/decisions/0009-odata-agent-vmesto-cfe).

<Warning>
  **Главное правило: коммитим так, будто репо уже публичный.** Открывать будем вместе с историей — всё, что хоть раз попало в коммит, станет видно всем. Вычищать историю потом дороже, чем не записать сейчас.
</Warning>

Это отличается от схемы cfe ([0008](/decisions/0008-dev-prod-repo), два репо dev/prod): у агента один репо с самого начала. Внутренняя кухня — журналы прогонов, стенд, задачи — живёт здесь, в базе знаний, а не в репо.

## Что лежит в репо

```text
bilem.agent/
├── README.md          — что это, для кого, статус, как запустить спайк
├── spike/
│   └── setup-spike.ps1 — прототип онбординга (PowerShell)
├── docs/
│   ├── onboarding.md   — шаги подключения базы и запасные пути
│   └── known-issues.md — справочник: признак → причина → что делает скрипт
└── src/               — сама программа (позже, когда выберем язык)
```

`.gitignore` — под выбранный язык, когда будет `src/`. Лицензия (MIT, [0007](/decisions/0007-publichnyj-repo-mit)) — перед открытием.

## Что в репо не попадает никогда

- Пароли, токены, ключи (в том числе `BLM-…`), строки подключения с паролями.
- Адреса и имена нашей инфраструктуры: стенд, его базы и публикации (`lakomka`, `1c.bilem.dev`), IP локальной сети и Tailscale (`10.*`, `192.168.*`, `100.*`), имена машин и учётных записей Windows.
- Пути и имена наших баз (`C:\ip_primin\…`): в примерах — нейтральные `C:\Bases\Demo`, `-AdminUser Администратор`.
- Данные из баз 1С (даже учебных): названия организаций и контрагентов, суммы, скриншоты, выгрузки `$metadata` с данными.
- Журналы прогонов со стенда (`C:\ProgramData\Bilem\…`), `.cred`, дампы.
- Внутренняя кухня: `CLAUDE.md` с деталями стенда, `.mcp.json`, задачи агентам, обсуждения, имена клиентов и лидов. Всё это — в базе знаний.

## Перед каждым push — проверка

Из корня репо (Git Bash или PowerShell с git):

```bash
git grep -n -i -E "lakomka|bilem\.dev|ip_primin|BLM-|password=|pwd=|\b(10|100|192\.168)\.[0-9]+\.[0-9]+" -- . ":!docs/known-issues.md"
```

Пусто — можно пушить. Нашлось — убрать до коммита. Закоммитили случайно и ещё не запушили — `git commit --amend` / переписать локальную историю. Запушили — сразу сказать Славе, не прятать.

## Как коммитим

- Ветка `main`. Пока коммитит один человек/агент — напрямую; когда подключится Станислав — ветки `agent/<slug>` и PR.
- Коммиты по-русски, по сути: «Спайк: права на базу только у пула IIS», а не «fix». Один коммит — одно изменение.
- Каждая найденная на прогоне проблема = правка в скрипте + строка в `docs/known-issues.md` (признак, причина, что делает скрипт) — без подробностей нашего стенда. Подробный разбор прогона — в [журнале спайка](/stand/agent-spike-log).
- README — по-русски, для человека со стороны: что такое Bilem Agent, статус (спайк, не для прода), требования (Windows, платформа 1С 8.3, IIS, права администратора), как запустить спайк на **копии** базы, что он меняет на машине.
