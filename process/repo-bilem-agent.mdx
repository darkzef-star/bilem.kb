**Репо:** `skp-kz/bilem.agent` · **Видимость:** закрытый сейчас, потом откроем **как есть, со всей историей** · **Решение Славы:** 18.10.2026

Bilem Agent — Windows-программа: 1С (OData на 127.0.0.1) → MCP-сервер для ИИ. Почему так — [0009 · OData + Bilem Agent вместо cfe](/decisions/0009-odata-agent-vmesto-cfe). Язык — [0011 · C# на .NET Framework 4.8](/decisions/0011-csharp-net48).

<Warning>
  **Главное правило: коммитим так, будто репо уже публичный.** Открывать будем вместе с историей — всё, что хоть раз попало в коммит, станет видно всем. Вычищать историю потом дороже, чем не записать сейчас.
</Warning>

Это отличается от схемы cfe ([0008](/decisions/0008-dev-prod-repo), два репо dev/prod): у агента один репо с самого начала. Внутренняя кухня — журналы прогонов, стенд, задачи — живёт здесь, в базе знаний, а не в репо.

## Что лежит в репо

```text
bilem.agent/
├── README.md            — что это, для кого, статус, как запустить
├── spike/
│   ├── setup-spike.ps1   — прототип онбординга (PowerShell)
│   └── mcp/              — прототип MCP-сервера (Node)
├── docs/
│   ├── onboarding.md     — шаги подключения базы и запасные пути
│   ├── rights.md         — права пользователя bilem
│   └── known-issues.md   — справочник: признак → причина → что делаем
└── src/                 — сама программа (C#, ТЗ v0.1)
```

`.gitignore` — под язык. Лицензия (MIT, [0007](/decisions/0007-publichnyj-repo-mit)) — перед открытием.

## Что в репо не попадает никогда

- Пароли, токены, ключи (в том числе `BLM-…`), строки подключения с паролями.
- Адреса и имена нашей инфраструктуры: стенд, его базы и публикации (`lakomka`, `1c.bilem.dev`), IP локальной сети и Tailscale (`10.*`, `192.168.*`, `100.*`), имена машин и учётных записей Windows.
- Пути и имена наших баз (`C:\ip_primin\…`): в примерах — нейтральные `C:\Bases\Demo`, `-AdminUser Администратор`.
- Данные из баз 1С (даже учебных): названия организаций и контрагентов, суммы, скриншоты, выгрузки `$metadata` с данными.
- Журналы прогонов со стенда (`C:\ProgramData\Bilem\…`), `.cred`, дампы, токены MCP.
- Внутренняя кухня: `CLAUDE.md` с деталями стенда, `.mcp.json`, задачи агентам, обсуждения, имена клиентов и лидов. Всё это — в базе знаний.

## Перед каждым push — проверка

Из корня репо (Git Bash или PowerShell с git):

```bash
git grep -n -i -E "lakomka|bilem\.dev|ip_primin|BLM-|password=|pwd=|\b(10|100|192\.168)\.[0-9]+\.[0-9]+" -- . ":!docs/known-issues.md" ":!**/package-lock.json" ":!**/packages.lock.json"
```

Lock-файлы зависимостей исключены (номера версий вида `10.7.4` похожи на IP) — их можно коммитить. Пусто — можно пушить. Нашлось — убрать до коммита. Закоммитили случайно и ещё не запушили — `git commit --amend` / переписать локальную историю. Запушили — сразу сказать Славе, не прятать.

## Как коммитим

- Ветка `main`. Пока коммитит один человек/агент — напрямую; когда подключится второй разработчик — ветки `agent/<slug>` и PR.
- Коммиты по-русски, по сути: «Спайк: права на базу только у пула IIS», а не «fix». Один коммит — одно изменение.
- Каждая найденная проблема = правка в коде + строка в `docs/known-issues.md` (признак, причина, что делаем) — без подробностей нашего стенда. Подробный разбор — в журналах ([спайк](/stand/agent-spike-log)).
- README — по-русски, для человека со стороны: что такое Bilem Agent, статус, требования (Windows, платформа 1С 8.3, IIS, права администратора), как запустить на **копии** базы, что меняется на машине.
